# Second bounded routing acceptance run

This run was authorized for at most three repair iterations. It did not establish production readiness. No new global hook registration or source deployment occurred. All model work used authenticated native subscription clients; hooks themselves made no model requests. Private generated evidence and account-specific configuration are excluded from this repository.

## Claude Code: newly observed boundaries

The treatment and control used the same neutral parent request, model, restricted CLI settings and observational plugin. Unlike the previous experiment, the observer admitted ordinary child prompt variants in both arms. Both parent instruction-file inventories were empty. The ambient `context-meter` plugin, its connected local MCP server/tool, and a 209-character engine MCP-instruction attachment remained in both arms. This run does **not** establish that all non-vendor guidance or ambient plugins were absent. Each arm started an actual worker, with independently correlated agent ID, worker turn, model and four worker-tagged attachment records.

A process-level read sandbox denied access to specified existing user instruction, memory and skill sources. Five local canary reads were denied before inference. Additional known ancestor instruction sources were also denied for the actual pair. The observational plugin retained attachment hashes and origins rather than their content. Both workers reported the same native Haiku model; this is not evidence of quota savings. The final inventory has four attachments per worker, but the step-time counter was zero: attachment records arrived through a different event ordering. It is a final observed inventory, not proof that all four attachments were inspected before inference.

In the treatment arm, the native routing hook supplied the exact frozen numbered stage/DoD packet, `haiku` alias and `low` effort. Its packet hash matched the actual worker's turn input. The worker returned exactly `13`; the signed completed observation matched the resolved native model, current source stamp and policy. In the control arm, the worker instead received the ordinary request, without that packet or a routing receipt. This proves delivery of the hook-generated packet at the measured dispatch boundary.

The native API does not expose the worker's complete static system context. Worker-tagged attachments are now measured independently; they do not substitute for an unavailable complete inventory. The sandbox covers the named known sources and does not prove absence of every possible undisclosed host input.

The control dispatch used the native background default. Its launch and worker inference were observed, but the controller did not retain the subsequent worker output. Therefore exact-output completion for the control remains **Open**. The controller's `pair-observed-awaiting-review` label does not mean the complete experiment passed. The observer saw two model steps in ON and three in OFF. The background completion started another parent turn despite the per-turn cap; a per-turn limit is not a whole-process inference budget. These are observed steps, not a measured subscription-quota conversion. No further model run was performed after the iteration limit.

## Codex: corrected launch, unresolved interception

1. The corrected CLI argument parser, ChatGPT subscription status and empty global/project AGENTS renderer checks passed. Actual launch then rejected the non-Git fixture before inference.
2. A disposable Git repository satisfied that prerequisite without skip/trust flags. The invocation produced native events but no observed dispatch or new guard receipt. Its error and answer content were mistakenly discarded, leaving the cause unproven. An exit code of zero does not prove a model inference or hook outcome.
3. The final controller retained bounded actionable diagnostics. Native startup rejected its generated MCP configuration before any events: `invalid transport` for a quoted server key. No native hook result or worker-model binding was proven. No fourth correction was attempted.

These failures belong to test setup and diagnostic retention, not evidence that a model cannot perform the underlying task. The production routing requirement remains **Open** in Codex.

## Required preflight improvements

- Validate the complete effective configuration through a renderer/startup check; `--help` proves argument syntax, not semantic configuration validity.
- Verify the disposable repository root and explicit prompt input before inference.
- Preserve bounded error and answer diagnostics, actual tool arguments, worker completion and native receipt outcomes for every attempt.
- Read actual receipt schemas and native foreground/background defaults before writing acceptance conditions. Bound automatic background-completion turns separately from a per-turn cap.
- Remove ambient plugin-directory environment settings before launch, assert an allowed plugin inventory, and assert that no plugin starts an unlisted MCP server/tool; distinguish engine attachments from connected servers.
- Use the same admission logic in treatment/control. Record completed worker output by agent identity, including background completion.
- Keep operator-defined capability/rank policy separate from measured model capability, billing and quota savings.

## Deployment decision

Independent Astra review verified the signed ON and packet-delivery claims, and identified the retained ambient plugin, MCP instruction attachment and event-ordering limits. Only the narrow packet-delivery, signed ON completion and named-source/final worker-attachment checks have fresh positive evidence. Automatic production planning, natural-language model override, the control's exact output, full worker static context and Codex interception remain unresolved. A global routing registration would claim or enforce more than these checks support, so it was withheld. Existing settings and unrelated hook permissions were preserved.
