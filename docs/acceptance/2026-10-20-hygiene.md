## Bounded native attempts

Each client first used three meaningful native attempts. After explicit additional authorization, exactly one final public-adapter attempt ran per client, four per client in total. Subscription authentication was used without supplied model API keys. No fifth attempt was executed.

Codex was version `0.163.0-alpha.10.2`. Attempt 1 observed a real PreToolUse and preserved the prior bytes, but the nested macOS sandbox prevented the patch itself. A model-free native command test reproduced `sandbox_apply: Operation not permitted`. Removing only the test's outer source-isolation sandbox, while retaining the native workspace-write sandbox, made the same model-free write test pass. Attempts 2 and 3 then patched the controlled file successfully and produced the hygiene hook's own native `blocked` Stop result. Attempt 3 also denied the next patch before its target existed. The corrected runs retained configuration-level instruction-file suppression; they do not claim operating-system read denial of instruction sources during the actual write.

Claude Code was version `2.1.302`. Its first Write succeeded, but a one-turn cap ended execution before Stop. The next two bounded trials permitted the final response and observed Write followed by a Stop response containing the guard's `decision: block`. A native model observer capped forwarding at two requests per successful arm; five requests were forwarded across the initial three attempts, followed by two in the separately authorized final-adapter trial. Native startup preflight used outbound-network denial and recorded empty observable instruction-file/MCP/skill inventories. Vendor instructions/plugins were not claimed absent. The controller's final turn-cap exit is a bounded abort after the measured block, not normal successful completion.

No paid OFF-control was run for this new hygiene experiment. Actual host hook output, matching native identities, signatures, pending state and filesystem checks support the stated block observations. The fixture supplied a true preflight review (and a baseline workflow plan where required); automatic planning or autonomous semantic review was not accepted by this test.

## Source and rollback qualification

An independent lead verifier checked the native identities, exact patch/Write bytes, original Old hashes, absent denied target and signed records. The Claude snapshot predates archive identity hardening; its measured pre-edit/Stop and supporting inspection/locking function ASTs were unchanged. The initial guard-only experiment was not represented as the exact final artifact. A later explicitly authorized native trial froze all 14 current public Python files and exercised the final public adapter. Engine reminder attachments were observable in that trial; user instruction-file inventories were empty, but total context isolation is not claimed.

Astra review found lexical-symlink normalization, missing-helper error handling, incomplete source-version dependencies, shell-alias delegation and case-insensitive file-identity defects. The implementation and regression tests were corrected. The case-only alias bug was reproduced before correction; after correction the live originals remained present and no archive was created for the refused operation.

Temporary native Codex source routing was restricted to exact disposable test roots, backed up and restored byte-for-byte in finally blocks. Native hook definition hashes and trust records were not forged or bypassed. The disconnected acceptance experiments did not enable global hygiene policy. Any operator installation is a separate action with a recoverable configuration/source record, not evidence of universal adoption.

A separate component-only check invoked the guard against a real existing project, denied an unreviewed edit and verified unchanged target and archive bytes. That observation is explicitly not proof of native global activation on that project. Project age alone is not a code exemption; operator/client adoption remains a distinct acceptance requirement.

Raw native identifiers, personal project names, local paths, logs, account metadata, private receipts and source snapshots remain private. The public report is sanitized. Supporting instructions must not be advertised as an unconditional 100% enforcement guarantee.

## Final adapter and compatibility verification

The final Codex native trial completed the actual patch, ran public PostToolUse and produced the hygiene hook's native blocked Stop status. The final Claude native trial completed Write, public PostToolUse and the Stop block; its four signed records matched one native session/prompt and the frozen source. The observer capped that Claude trial at two forwarded model requests. The operator's unrelated existing canary retained its hash.

Four additional model-free compatibility replays used minimal wrappers around the operator's existing legacy cores, preserving their ledger syntax instead of overwriting those cores with public defaults. Fresh/existing roots on both clients passed the same before/after review, backup, next-edit, Stop, release and unverified-shell checks. These are compatibility replays, not further native model invocations.

The code enforces structural review gates and conservative transfers for supported calls. It cannot certify that every agent's usage/dependency note is correct, that no external consumer references a file, or that a host invokes hooks for every possible operation. Customer instructions must preserve those distinctions.
