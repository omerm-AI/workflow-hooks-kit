# Claude Agent request binding

`claude-plugin/workflow-hooks-kit/scripts/delegation_binding.py` provides a bounded, fail-closed validator for binding one native Claude `Agent` request to a prepared stage in a workflow ledger. It exports `build_prompt(stage)` and `validate_request(ledger, tool_input, allowed_models)`. The module is not wired into `delegation_gate.py` or `tool_scope_hook.py`; the existing gate still checks only that an active substantial plan exists. No request-binding enforcement is active until a native hook integration calls this validator and is independently accepted.

The ledger must have schema version `1`, task kind `substantial`, state `in-progress`, and one to twenty consecutive stages with unique names and nonempty outputs. Each stage uses the established fields: number, name, worker identity and model declaration, effort and rationale, inputs, boundaries, dependencies, definition of done, outputs, and QA check/expected. Runtime stages may also carry bounded `attempts`; those records are shape-checked and ignored by the canonical packet, without applying retry or escalation policy. QA may contain mutable evidence, verdict, and reviewer identity; those values also do not enter the prompt or stage hash. Optional literal assertions are validated against the core schema: up to eight `{path, expected_text}` entries, with safe relative paths that match declared outputs and expected UTF-8 text up to 16 KiB. Assertions are included in the canonical packet as frozen criteria. Unknown stage or QA fields fail closed. The ledger and request mappings are read without mutation.

The native request must contain exactly `description`, `prompt`, `model`, and `subagent_type`. Description must equal `[workflow-stage:N] ` followed by that frozen stage's exact name; unchecked suffix text is rejected. The only accepted `subagent_type` is `general-purpose`; `worker_id` remains a logical ledger identity and is not treated as a Claude subagent type. The requested model must exactly equal the stage's alias and must resolve through the caller's explicit trusted alias-to-native-model map. There is no fallback or implicit normalization.

`build_prompt` emits `WORKFLOW_STAGE_REQUEST_V1` followed by one canonical UTF-8 JSON packet. The packet includes only the frozen fields and immutable QA criteria. `validate_request` requires the supplied prompt to equal those bytes exactly, then returns an immutable mapping with schema, selected stage, logical worker ID, requested and resolved model names, and SHA-256 hashes of the canonical stage packet and exact prompt. Payloads, strings, lists, and encoded packet size are bounded. A known observation from an earlier native Claude Code run recorded requested alias `haiku` and resolved model `claude-haiku-5-5`; that pair is suitable as an explicit fixture, not an automatically trusted global model registry. See [the observer evidence](delegation-observer.md).

This validates routing and delivery of declared criteria. It does not authenticate the hook caller or model, prove that a worker ran or followed the prompt, inspect output quality, or establish semantic QA. The existing PostToolUse observer records native response status and `resolvedModel`, but it is not yet connected to this validator's result. A separate companion PreToolUse hook cannot safely veto completion QA while the legacy core may persist QA concurrently; integration must address that ordering before claiming enforced worker-to-stage binding or QA enforcement. No model API or CLI is used.

## Native input-rewrite capability sample

A separate isolated Code Local subscription experiment established that a PreToolUse hook can return `updatedInput` without returning an explicit permission approval. The user prompt requested a worker result of `13`; the test hook replaced the worker prompt with a fixed request for `17`. The native worker pane displayed the replaced prompt and actual result `17`, and PostToolUse metadata contained the matching rewritten-prompt hash, actual agent identity hash, requested alias `haiku`, resolved model `claude-haiku-5-5`, and completed status. Signed native callback receipts were independently matched to native session/prompt identities and code/data versions. Temporary project handlers were removed and the prior project configuration restored exactly.

This establishes the tested native argument-replacement path, not deployment of this validator. The test-only plan was closed as blocked with no workflow QA PASS. Its first fixture candidate failed before worker execution because the receipt directory had not been initialized; that failure was retained and fixed before the successful native sample. A language-compliance failure in the successful rewrite run was recorded separately. No model API or model CLI was called. A production adapter must still bind the selected stage and rewritten packet to the actual post-dispatch event before claiming delivery.

The attempted native strict adapter was not accepted: its actual Agent input-shape test failed, and an independent denial-path probe lacked a signed failure receipt. Investigation stopped at its bounded limit. [The archived candidate](https://github.com/omerm-AI/workflow-hooks-kit/tree/archive/strict-stage-candidate-10) is preserved for review and was not globally deployed. This branch retains only the unwired request validator and the previously accepted prerequisite guard.
