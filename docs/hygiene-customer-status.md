## What cleanup allows

Cleanup is a later, reviewed action. Required code, documentation, configuration, tests, assets, and dependencies stay where the project needs them. The guard does not decide that a source file is obsolete because of its name or age.

Archiving is limited to an explicitly reviewed, byte-identical duplicate of a supported media or document file, with a separate kept original and no detected local references. The currently supported extensions are media formats and PDF; this does not include arbitrary text, Markdown, Word, spreadsheet or source files. Other reviewed, supported unreferenced media/PDF assets may move to `Assets` with recovery evidence. If use or dependencies are uncertain, keep the file and ask the project owner. There is no permanent deletion.

## Installation

Use the [reviewed public GitHub preview](https://github.com/omerm-AI/workflow-hooks-kit/tree/hygiene-file-tools-preview-2026-10-20) on macOS or Linux with Python 3.9 or newer. Follow the [customer installation guide](customer-install.md): inspect the pinned checkout, run the model-free smoke check in a new disposable home, install into a different disposable home, and verify the selected client's native trust and canary before installing the real account. Codex's fresh-profile login and trust are still prerequisites; do not copy credentials or use an API-key fallback.

For a guided setup, give the selected agent its actual platform prompt: [Codex installation prompt](../prompts/install-hygiene-codex.he.txt) or [Claude Code installation prompt](../prompts/install-hygiene-claude-code.he.txt). Each prompt pins the GitHub preview and spells out the checks and stop conditions. Installation changes host hook settings and runtime; it does not modify project files or perform retrospective cleanup.

After installation, the host's `WORK_STANDARDS.md` and the relevant [hygiene contract](hygiene-enforcement.md) must be made available for later file work. The installer does not add project instructions or load the contract automatically.

## Existing folders that already contain clutter

1. Open the intended project and first list candidates without moving files. Exclude `Old`, Git metadata and dependency directories from routine inventory. This requested audit is separate work, not an automatic installation effect.
2. Inspect current references, declared external/dynamic use and concurrent work. Keep required source/configuration in place; do not infer obsolescence from age, extension or a version-looking name.
3. Submit only eligible duplicate/archive or supported asset moves through the installed hygiene sentinel, using actual hashes. Preserve unresolved and unsupported files and ask the owner about ambiguous use.
4. Verify the actual active tree, dated manifests, byte hashes and recovery. Report moved, kept and unresolved items separately. A reviewed old-folder cleanup is not proof of adoption by an already-running session.

The current runtime cannot automatically organize every historical draft or helper type. The package is a bounded preview with documented gaps, not a fully certified all-project cleanup service.

## Selected limited mode

`--hygiene-file-tools` is the explicitly limited option: known native file saves and Stop require review and verified beforeimages. Shell/connector writes are outside that gate and retain baseline behavior. It does not certify all saves in every tool. The separate strict `--hygiene-enforcement` option blocks unknown shell/connector calls and must never be silently substituted. Open each intended project at its exact working root; the hook does not automatically discover every nested Git boundary.

The latest published-tag replay and Claude default-settings zero-model witness are recorded in [limited-mode acceptance](acceptance/2026-10-20-file-tools.md). They do not remove the separate fresh-profile native canary requirement.
