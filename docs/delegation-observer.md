# Native Agent result observer

`delegation_observer.py` is a fail-open metadata observer for native Claude `PostToolUse` events where `tool_name` is exactly `Agent`. It does not handle `spawn_agent`; the Codex response contract for that tool is not verified here. The observer never approves or denies a tool, evaluates task quality, calls a model, or reads transcripts, credentials, or result content.

The input must include `session_id`, one consistent `prompt_id` or `turn_id`, `tool_use_id`, `tool_input`, and `tool_response`. It accepts response status `completed` or `async_launched`, `agentId`, optional `resolvedModel`, and optional `modelsUsed`. The requested model comes from `tool_input.model`. Unknown statuses and malformed or incomplete metadata produce a short `systemMessage` and no observation or receipt. Input is capped at 1,000,000 bytes; model labels are at most 128 characters; `modelsUsed` has at most 16 entries.

The observer writes one atomic `latest-observation.json` envelope in the required existing state directory. It hashes the session, native turn, tool-use ID, prompt, and agent ID. Multiline prompts are accepted and hashed as supplied. Prompt text, descriptions, raw identifiers, tool output, and result content are never retained. Requested/resolved model labels, the bounded `modelsUsed` list, status, event/tool names, and a SHA-256 fingerprint of the observer plus receipt helper source are retained. The envelope stores the observation and its receipt marker. The receipt version also binds the canonical metadata hash, so changing a recorded model or status invalidates receipt verification. The state directory must be a real owner-owned directory with no group/other permissions. The state file and empty lock are owner-only; the state file is capped at 4,096 bytes. A two-second local file lock serializes atomic replacements, so concurrent events leave only the latest observation.

The observer first writes the observation, then creates a local signed `PostToolUse` receipt with outcome `success` through `hook_receipt.py`, and atomically stores the marker with the observation. That outcome means only that metadata recording succeeded. A marker is returned only after both writes and receipt creation succeed. The returned message says `completion unverified` for `async_launched`; `completed` says task QA is required. Neither status proves semantic success, model compliance, review, or completion of the parent task. If receipt creation or the final write fails, the observer returns a bounded skipped message and does not emit a marker.

The observer is not registered by this change. Hook installation and native trust review are separate. Unit tests prove local parsing, bounded storage, hashing, file protections, concurrency, and receipt use; they do not prove native activation or model identity. Actual model/worker proof still requires an independently observed native event and review of the worker result.

## Controlled native pilot

A fresh Code Local subscription session ran the same neutral Agent-only prompt previously denied by the prerequisite guard. A project-only native UserPromptSubmit test fixture supplied a frozen plan through the real plan API; it did not inject planning instructions into the user prompt or certify QA. The actual guard then permitted one Agent call. The worker details pane showed Haiku 5.5 and the exact result `13`. The native PostToolUse observer reported requested model `haiku`, resolved model `claude-haiku-5-5`, and status `completed`; its hashed agent identifier matched the independently viewed native worker. Three separate callback receipts (test preparation, prerequisite guard, observer) matched independently obtained native session/prompt IDs and their exact code/data versions, and were verified and consumed once.

This proves the tested prepared-dispatch path and native metadata recording. The test-only preparation is not evidence of a general automatic planner, and observing the resolved model does not enforce its match to a frozen route. The complete workflow received no QA PASS: its frozen fixture boundary forbade tools while Auto mode used the native SubagentHandback reporting tool, and the parent did not have a full QA packet. A controlled native cleanup carried the record and honestly marked it blocked with pending QA; the underlying record was inspected independently. Temporary project handlers were removed and the exact prior project configuration restored. The observer is still not installed globally by this pilot. No model API or model CLI was called.
