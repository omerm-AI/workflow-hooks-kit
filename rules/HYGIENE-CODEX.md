# Codex project hygiene contract

Acceptance status: experimental implementation; specified native guard branches are accepted; global customer rollout is not yet accepted. This instruction is not an executable security boundary and must not be sold as one.

Apply this contract to each actual project root used by the task, including nested working directories. Keep current deliverables and required source, tests, configuration, dependencies and active diagnostic files. Do not infer obsolescence from age or filename.

Before every supported file edit, obtain the executable hygiene gate's approval for the exact path and current hash. Preserve the previous bytes, relative path and timestamp in the same project's dated Old archive. If the gate is missing, unavailable, rejects the operation or has an outstanding review, do not proceed to the next edit.

After each edit and before completion, review actual changed files, local references, declared external dependencies and concurrent work. Record keep, asset, archive or unresolved decisions with reasons. Ask the user about unresolved use; do not guess. Helpers belong in Assets unless the project requires their existing location. Apply the same rule recursively while preserving required project structure.

Archive only evidenced obsolete files. Preserve names, relative paths, timestamps, byte hashes and a dated recovery manifest. Never permanently delete, overwrite an archive or overwrite a live file during restoration. Do not relocate credentials, locks or active dependencies. Code may refuse an archive even after an agent recommends it.

A saved setting, agent declaration, empty Old directory or passing script replay is not proof of native hook activation. Report native acceptance separately for PreToolUse and Stop, including bypasses and unsupported shell/MCP paths. No unconditional guarantee is implied. Install and trust the executable hooks through the actual client before using this contract with customer work.
