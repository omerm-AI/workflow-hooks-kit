ההתקנה אינה משנה קבצי פרויקט ואינה מבצעת ניקוי גורף בדיעבד. ההגנה חלה על פעולות עתידיות נתמכות בתיקיות חדשות וקיימות.

1. בצע בפועל: `git clone --branch hygiene-preview-2026-10-20 --depth 1 https://github.com/omerm-AI/workflow-hooks-kit.git workflow-hooks-kit-preview`, היכנס לתיקייה, ודא `git describe --tags --exact-match HEAD` מחזיר את התג ו־`git status --short` נקי. קרא את `README.md`, `install.py`, `docs/hygiene-enforcement.md`, `docs/hook-status.md` ו־`docs/acceptance/2026-10-20-hygiene.md`. אל תשתמש ב־fork, ענף אחר או עותק ששונה.
2. בדוק בחשבון Codex אם כבר יש kit, plugin או core מותאם מקביל, או runtime אחר שתופס אותם אירועי hooks. אם יש התנגשות, עצור והצג נתיבים וצעד בטוח. אל תיצור כפילות, תדרוס, תסיר או תמזג runtime אחר.
3. הרץ בדיקת עשן ללא מודל עם נתיב מוחלט חדש שעדיין לא קיים. אל תיצור את התיקייה מראש. לדוגמה: `python3 tools/hygiene_smoke.py --home /absolute/new/codex-smoke-home --platform codex`. הבדיקה צריכה לעבור על coexistence, התקנה חוזרת, שערים והסרת רישום זמני. אם הבית קיים, הקובץ חסר או הבדיקה לא עוברת, עצור ודווח.
4. לפני הפעלת הפרופיל, בחר נתיב מוחלט שני שטרם קיים, נפרד מבדיקת העשן, והתקן בו בפועל: `python3 install.py --platform codex --home /absolute/new/codex-native-home --hygiene-enforcement`. בדוק שנוצרו ארבע הגדרות ההוק ושהמתקין לא שינה קבצי פרויקט. רק אחרי ההתקנה הרץ `CODEX_HOME=/absolute/new/codex-native-home/.codex codex login status`. אם אינו מחובר, בקש ממני להשלים כניסת מנוי רגילה באמצעות `CODEX_HOME=/absolute/new/codex-native-home/.codex codex login`, בלי מפתח API ובלי להעתיק credentials. הפעל `CODEX_HOME=/absolute/new/codex-native-home/.codex codex -C /path/to/disposable-project`. בתוך הפרופיל פתח `/hooks` ובקש אישור אמון לארבע ההגדרות שנבדקו. גילוי ארבעת ההוקים בפרופיל הוכח ללא מודל; canary נייטיבי בפרופיל החדש עדיין דורש כניסה, אמון וראיות בפועל. אל תתחיל inference כשהפרופיל אינו מחובר או ההוקים אינם מהימנים.
5. בצע canary בפרויקט זמני בלבד ואמת אירוע native, מקור ההוק ותוצאת קובץ בפועל. מסלול הפרופיל זוהה ללא מודל; הבדיקה הנייטיבית עצמה עדיין **Open** עד כניסה, אישור אמון ותוצאה מוכחת. אין להחשיב זיכרון, סירוב מילולי של המודל או קובץ הגדרות כראיית חסימה בקוד.
6. השתמש רק בהתחברות המנוי הקיימת של לקוח Codex. אין להשתמש במפתח API שסופק, להעתיק קובצי credentials או לבצע fallback ל־API או לשירות בתשלום. אם אין התחברות מנוי פעילה, עצור והצג את שלב הכניסה.
7. בדוק managed settings ודריסות ברמת פרויקט. אל תניח שסשנים שכבר פתוחים טוענים הגדרות חדשות; בדוק בנפרד או דווח **Open**. אל תתקין בחשבון האמיתי לפני שעשן, התקנת הבית השני ו־canary native הצליחו בגבול הנבדק.
8. אחרי canary מצליח, התקן לחשבון Codex בלבד: `python3 install.py --platform codex --hygiene-enforcement`. Strict חוסם shell רגיל שאין לו גבול כתיבה מאומת, כולל build או generator. הסבר את ההשפעה והיקף הראיות לפני ההתקנה. בקשתי המפורשת להתקין מאשרת את opt-in. בדוק את נתיבי ההתקנה ושימור הגדרות זרות.
9. המתקין מתקין `WORK_STANDARDS.md` בתיקיית kit, אך לא עורך `AGENTS.md`/הוראות פרויקט ולא טוען אוטומטית את `rules/HYGIENE-CODEX.md`. בעבודות קבצים עתידיות הורֵה לסוכן לקרוא את שני מסמכי המדיניות, או הוסף הפניה מבוקרת להוראות הפרויקט. אל תסתמך על memory. כש־hook חוסם כלי נתמך, קרא את הודעתו והמשך לפי ה־ledger או ה־hygiene sentinel המדויק שהיא מחזירה.
